## F1. 티켓 스캔 & 데이터 수집

### F1.1 카메라 캡처

| 항목 | 내용 |
|------|------|
| **설명** | 앱 내 카메라로 낙첨 복권을 실시간 촬영하여 데이터 추출 |
| **우선순위** | P0 (MVP) |
| **탭** | 스캔 탭 |
| **선행 조건** | 카메라 권한 허용, 로그인 상태 (Free 이상) |
| **정상 플로우** | 카메라 실행 → 복권을 프레임에 맞춤 → 촬영 → OCR 처리 → 결과 표시 |
| **예외 처리** | 흔들림/저조도 → 재촬영 안내, OCR 실패 → 수동 입력 유도 |
| **비즈니스 룰** | 일일 스캔 한도: 국가별 설정 (기본 30회/일) |
| **Guest 접근** | 불가 → "회원가입 후 이용 가능합니다" |

### F1.2 갤러리 업로드

| 항목 | 내용 |
|------|------|
| **설명** | 기존에 촬영한 복권 사진을 갤러리에서 선택하여 업로드 |
| **우선순위** | P0 (MVP) |
| **비즈니스 룰** | EXIF 촬영 시간이 7일 이상 경과한 이미지는 경고 표시 |
| **파일 제한** | JPEG/PNG만, 최대 10MB |

### F1.3 바코드/QR 스캔

| 항목 | 내용 |
|------|------|
| **설명** | 복권의 바코드 또는 QR코드를 인식하여 데이터 추출 |
| **우선순위** | P1 |
| **비고** | 국가/복권마다 바코드 유무 상이, 한국 로또는 QR 있음 |

### F1.4 수동 입력

| 항목 | 내용 |
|------|------|
| **설명** | OCR 실패 시 사용자가 직접 회차, 번호 등을 입력 |
| **우선순위** | P1 |
| **입력 필드** | 게임 종류, 회차, 선택 번호들, 구매일 |
| **비즈니스 룰** | 수동 입력 시 기본 포인트의 50%만 지급 (어뷰징 방지) |
| **검증** | 번호 범위 유효성 (1~45), 중복 번호 불가, 회차 존재 여부 |

### F1.5 OCR 결과 확인/수정

| 항목 | 내용 |
|------|------|
| **설명** | OCR 추출 결과를 사용자에게 보여주고, 오류 시 수정할 수 있게 함 |
| **우선순위** | P0 (MVP) |
| **표시 항목** | 게임 종류, 회차, 번호, 구매일 |
| **비즈니스 룰** | 사용자가 수정한 경우, 수정 이력을 별도 기록 (어뷰징 분석용) |

## F2. 검증 (Anti-Fraud)

### F2.1 Hash 기반 중복 차단

| 항목 | 내용 |
|------|------|
| **설명** | 동일 티켓이 여러 번/여러 사용자에 의해 등록되는 것을 차단 |
| **우선순위** | P0 (MVP) |
| **Hash 생성** | `SHA-256(국가코드 + 게임코드 + 회차 + 선택번호 정렬)` |
| **판별** | `tickets.ticket_hash` UNIQUE INDEX 존재 여부 |
| **차단 시** | HTTP 409 + 사용자에게 "이미 등록된 티켓" 안내 |

### F2.2 메타데이터·시공간 검증

| 항목 | 내용 |
|------|------|
| **설명** | EXIF 데이터와 GPS를 분석하여 위변조/조작 탐지 |
| **우선순위** | P1 |
| **검증 항목** | EXIF 촬영 시간, GPS 좌표, 연속 등록 간 이동 속도 |
| **이동 속도 공식** | `v = 두 등록 건 사이 거리(km) / 시간차(h)` |
| **차단 기준** | v > 900km/h (항공기 초과) → GPS 조작 판정 |

### F2.3 Rate Limiting

| 항목 | 내용 |
|------|------|
| **설명** | 비정상 패턴(대량 실패, 반복 시도)에 대한 자동 제한 |
| **우선순위** | P0 (MVP) |
| **규칙** | 동일 IP 또는 기기에서 1시간 내 50회 실패 → 24시간 Lock |
| **일일 한도** | 국가별 `max_daily_scans` 설정값 적용 (기본 30회) |

### F2.4 낙첨 여부 확인

| 항목 | 내용 |
|------|------|
| **설명** | 해당 회차의 당첨 결과와 대조하여 실제 낙첨인지 확인 |
| **우선순위** | P0 (MVP) |
| **방법** | 추첨 결과 DB와 사용자 번호를 비교, 당첨 번호와 겹치지 않음을 확인 |
| **예외** | 5등 이하 소액 당첨은 정책에 따라 등록 허용/차단 선택 |
| **미발표 회차** | "대기(PENDING)" 처리 → 결과 발표 후 자동 검증 → 포인트 지급 |

## F3. 리워드 시스템

### F3.1 기본 포인트 지급

| 항목 | 내용 |
|------|------|
| **설명** | 검증 완료된 티켓 등록 시 기본 포인트 즉시 지급 |
| **우선순위** | P0 (MVP) |
| **기본 지급량** | 국가별 `base_reward_amount` 설정 (한국 기본 50P) |
| **구독자 배수** | 기본량 x 2.0 (한국 구독자: 100P) |
| **수동 입력** | 기본량 x 0.5 (50% 감산) |

### F3.2 미션 부스트

| 항목 | 내용 |
|------|------|
| **설명** | Free 사용자가 광고 시청 등 미션을 선택적으로 수행하면 추가 포인트 지급 |
| **우선순위** | P1 |
| **미션 종류** | 광고 시청(30초), 퀴즈 참여, 설문 응답 |
| **부스트 배수** | 기본 x 1.5 (미션 수행 시 50P → 75P) |
| **핵심 원칙** | **미션은 강제가 아닌 선택** — 미수행해도 기본 포인트는 지급 |

### F3.3 구독자 2배 적립

| 항목 | 내용 |
|------|------|
| **설명** | 구독자는 기본 적립의 2배를 자동으로 받음 |
| **우선순위** | P1 |
| **산출** | 기본량 x 2.0 (미션 수행 시: x 2.0 x 1.5 = 3.0배) |

### F3.4 Free Pass

| 항목 | 내용 |
|------|------|
| **설명** | 구독자는 미션 단계를 건너뛰고 즉시 등록 완료 + 2배 적립 |
| **우선순위** | P1 |
| **동작** | 검증 완료 즉시 포인트 지급 (미션 선택 화면 스킵) |

**보상 체계 요약표:**

| 유저 | 미션 | 기본량(50P 기준) | 배수 | 최종 |
|------|------|:---:|:---:|:---:|
| Free | 미수행 | 50 | x1.0 | **50P** |
| Free | 수행 | 50 | x1.5 | **75P** |
| 구독자 | 미수행 (Free Pass) | 50 | x2.0 | **100P** |
| 구독자 | 자발적 수행 | 50 | x3.0 | **150P** |

## F4. AI 번호 추천 (알고리즘)

> 상세 알고리즘 스펙은 `04_알고리즘_명세.md` 참조

### F4.1 추천 세트 자동 생성

| 항목 | 내용 |
|------|------|
| **설명** | 수집된 낙첨 데이터를 분석하여 매 회차 번호 추천 세트를 생성 |
| **우선순위** | P1 |
| **탭** | AI추천 탭 |
| **생성 시점** | 매 회차 추첨 결과 확정 + 데이터 수집 기간 종료 후 자동 생성 |
| **세트 수** | 회차당 3~5세트 (구독 플랜에 따라 차등) |
| **갱신 주기** | 주 1회 (한국 로또 기준 토요일 추첨 후 일요일 새 추천 생성) |

### F4.2 추천 열람

| 항목 | 내용 |
|------|------|
| **설명** | AI 추천 세트를 열람 (유료) |
| **우선순위** | P1 |
| **접근 권한** | 구독자: 전체 무제한, Free: 세트당 200P 차감 |
| **미리보기** | Free 사용자에게 1~2개 번호만 보여주고 나머지 블러 처리 (후킹) |
| **Guest** | 기본 통계만 열람 가능, AI 추천 열람 불가 |

### F4.3 분석 리포트

| 항목 | 내용 |
|------|------|
| **설명** | 수집 데이터 기반 통계/분석 정보 제공 |
| **우선순위** | P1 (기본 통계는 P0) |
| **무료 공개** | 최다/최소 출현 번호 (최근 10회), 기본 빈도 그래프 |
| **유료 (구독/500P)** | 연번 분석, 구간별 분포, 홀짝 패턴, 회차별 트렌드, 핫넘버/콜드넘버 |

### F4.4 개인 맞춤 추천

| 항목 | 내용 |
|------|------|
| **설명** | 해당 사용자의 과거 구매 번호 패턴을 분석하여 개인화된 추천 |
| **우선순위** | P2 |
| **접근 권한** | 구독자 전용 |
| **필요 조건** | 해당 사용자의 스캔 이력 10건 이상 |

### F4.5 적중 이력 추적

| 항목 | 내용 |
|------|------|
| **설명** | 과거 AI 추천 번호가 실제 당첨 결과와 몇 개 일치했는지 추적/공개 |
| **우선순위** | P1 |
| **목적** | 알고리즘 신뢰도 표시, 마케팅 활용 |
| **투명성** | 미적중 결과도 숨기지 않고 전체 공개 |

## F5. 로또 요리사 (커스텀 필터 번호 생성) ★ 프리미엄

> 상세 필터 스펙, 화면 와이어프레임, API는 `10_커스텀_필터_번호생성.md` 참조

**이 기능은 별도 탭(로또 요리사)으로 독립 제공되는 프리미엄 기능이다.**

### AI 추천(F4) vs 로또 요리사(F5) 차이

| 항목 | AI 추천 (F4) | **로또 요리사 (F5)** |
|------|:---:|:---:|
| 탭 | AI추천 탭 | **로또 요리사 탭** |
| 번호 결정 주체 | 시스템 (자동) | **사용자 (직접 조절)** |
| 사용자 개입 | 없음 (열람만) | **필터 가중치 조절** |
| 생성 시점 | 주 1회 배치 | **사용자 요청 시 즉시** |
| 비용 (Free) | 200P / 세트 | **100P / 세트** |
| 비용 (구독자) | 무제한 | **1일 1회 무료, 추가 50P** |
| 이력 관리 | 시스템 추천 이력 | **내가 만든 번호 전체 저장** |
| 적중 추적 | 시스템 추천 기준 | **내가 만든 번호 기준** |

### F5.1 20개 필터 가중치 조절

| 항목 | 내용 |
|------|------|
| **설명** | 5개 카테고리, 20개 분석 필터의 가중치(0~100)를 슬라이더로 조절 |
| **우선순위** | P1 |
| **카테고리** | [A] 빈도(4개), [B] 패턴(6개), [C] 수학(4개), [D] 이력(3개), [E] 개인(3개) |
| **최소 조건** | 최소 1개 필터의 가중치가 1 이상이어야 생성 가능 |

### F5.2 번호 생성 (포인트 차감)

| 항목 | 내용 |
|------|------|
| **설명** | 설정된 필터 가중치에 따라 번호 세트 생성, 포인트 차감 |
| **비용** | Free: 100P, 구독자: 50P (1일 1회 무료) |
| **결과** | 번호 세트 (6개) + 특성 분석 (홀짝, 합계, AC값 등) |
| **에러** | 필터 조건 과다 시 "조건이 너무 까다롭습니다" 안내 |

| 항목 | 내용 |
|------|------|

| **시스템 프리셋** | 트렌드 추종, 역발상, 균형 조합, 수학 최적화, 내 번호 중심 |
| **커스텀 프리셋** | 사용자가 자신의 필터 설정을 이름 붙여 저장 |

### F5.4 생성 이력 조회/적중 확인
