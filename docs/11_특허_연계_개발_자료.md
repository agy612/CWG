# 11. 특허 연계 개발 자료

> **문서 분류:** 사내 기밀 (CONFIDENTIAL)
> **용도:** 개발팀 ↔ 특허 변리사 커뮤니케이션
> **최종 수정일:** 2026-02-13
> **대상 특허:** 낙첨 결과 공 매치의 다채널 데이터 획득, 중복·위조 저지 및 현지화 가변형 검증을 포함하는 가치환원 시스템

---

## 1. 문서 목적

본 문서는 CWG ReturnValue의 **특허 청구항(Claims 1~10)** 및 **도면(도 1~4)**이 실제 개발 구현체에서 어떻게 실현되는지를 대응시킨 자료이다.

**활용처:**
- 개발팀: 각 기능이 특허의 어떤 청구항을 실현하는지 인지하고, 구현 시 특허 기술요소가 누락되지 않도록 참조
- 변리사: 개발 단계의 로직 도식화(플로우차트)를 통해 특허 청구항의 기술적 구성요소가 실제 시스템에서 동작하는 방식을 확인

---

## 2. 전체 시스템 로직 흐름도

> 본 섹션은 CWG ReturnValue 앱의 **모든 로직 흐름**을 도식화한 것이다.
> 변리사에게 시스템 동작의 전체 그림을 먼저 제공하고, 이후 섹션에서 각 흐름이 특허 청구항과 어떻게 대응하는지를 상세히 설명한다.

## 3. 특허 구조 요약

### 3.1. 발명의 명칭

**낙첨 결과 공 매치의 다채널 데이터 획득, 중복·위조 저지 및 현지화 가변형 검증을 포함하는 가치환원 시스템**

### 3.2. 청구항 요약 (Claims 1~10)

| 청구항 | 유형 | 핵심 기술요소 |
|--------|------|-------------|
| **1** | 독립항 | 전체 시스템 — 다채널 데이터 획득, 검증, 사용자 가치환원을 위한 데이터 셋트 활용 단계를 포함하는 가치환원(Value Return) 시스템 |
| **2** | 종속항 | 국가별 게임 결과 규격에 맞춘 데이터 해석, 자동/수동 분류 및 이벤트 활용 |
| **3** | 종속항 | 다채널 데이터 획득 모듈 — 바코드/QR, OCR, 이미지 촬영, 수동 입력, API 연동 |
| **4** | 종속항 | 고유 식별값(Hash) 생성 기반 중복/위변조 검증 |
| **5** | 종속항 | 프리미엄 접근권(Premium Access Right) — 가치환원 데이터 추적, 프리미엄 콘텐츠 접근권 제공 |
| **6** | 종속항 | 미션(Mission) 기반 가중치 정산 |
| **7** | 종속항 | 선택적 참여 — 미션 강제 차단 (미수행 시에도 기본 가치환원 보장) |

| **10** | 종속항 | 국가별 규제/정책에 따른 가변형 검증 구조 |

```
│  │ 최종 포인트 = base_reward × tier_mult × boost_mult │            │
│  │                                                    │            │
│  │  FREE + 미수행:      50 × 1.0 × 1.0 =  50P        │            │
│  │  FREE + Boost:       50 × 1.0 × 1.5 =  75P        │            │
│  │  SUBSCRIBER + Pass:  50 × 2.0 × 1.0 = 100P        │            │
│  │  SUBSCRIBER + Boost: 50 × 2.0 × 1.5 = 150P        │            │
│  └──────────────────────┬───────────────────────────┘            │
│                         │                                        │
│                         ▼                                        │
│  ┌──────────────────────────────────────────────┐                │
│  │ transactions INSERT (포인트 원장 기록)          │                │
│  │   type: SCAN_REWARD                           │                │
│  │   amount: 최종 포인트                           │                │
│  │   balance_after: 갱신 후 잔액                   │                │
│  │                                               │                │
│  │ users.point_balance UPDATE                    │                │
│  └──────────────────────────────────────────────┘                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**수동 입력 감산 (청구항 3 관련 보충):**

```
수동 입력 채널(F1.4)을 통해 입력된 경우:
  → manual_input_reward_rate 적용 (기본 0.5 = 50%)
  → base_reward = country_policies.base_reward_amount × 0.5
  → 이후 tier_mult, boost_mult는 동일하게 적용

예) FREE + 수동입력 + Boost:  50 × 0.5 × 1.0 × 1.5 = 37.5P → 반올림 38P
```

**청구항 요지:** 미션은 선택이며, 미수행 시에도 기본 가치환원은 보장

```
  │                      │
```

```
  → tier_mult = 2.0 자동 적용

  → tier_mult = 2.0, boost_mult = 1.5
  → 50 × 2.0 × 1.5 = 150P (최고 등급 보상)
```

```
CWG 플랫폼
    │
    │ 미션(광고 시청) 완료 콜백 수신
    │ → callback_id 검증
    │ → 광고 시청 시간(ad_watched_seconds) 확인
    ▼
사용자에게 Boost 포인트 지급
    │
    │ 광고비 수익 > 추가 포인트 비용
    └─ 차액 = 플랫폼 수익

핵심: 사용자는 포인트를 얻고, 광고주는 노출을 얻고,
      플랫폼은 차액 수익을 얻는 3자 Win-Win 구조
```

### 6.10. 청구항 10 — 국가별 가변형 검증 구조

**청구항 요지:** 국가별 규제/정책에 따라 검증 파라미터, 미션 정책, 처리 흐름을 가변적으로 조정

```
[가변형 정책 엔진]

country_policies 데이터 구조:
  {
    "country_code": "KR",              ← S410: 국가 식별
    "base_reward_amount": 50,           ← S420: 보상 파라미터
    "subscriber_multiplier": 2.00,
    "boost_multiplier": 1.50,
    "is_mission_enabled": true,         ← S430: 미션 활성화 여부
    "max_daily_scans": 30,              ← S430: 임계값
    "fraud_level": "NORMAL",            ← S430: 검증 강도
    "manual_input_reward_rate": 0.50,
    "subscription_price_monthly": 4900, ← S440: 현지 가격
    "subscription_currency": "KRW",
    "cash_withdrawal_enabled": false    ← S440: 현지 규제 반영
  }

신규 국가 추가 절차:
  1. country_policies에 새 레코드 INSERT
  2. game_configs에 해당 국가 로또 규격 INSERT
  3. 코드 변경 없이 즉시 서비스 확장 가능

→ 이것이 "가변형(Configurable)" 구조의 핵심
→ 코드 수정 없이 데이터만으로 국가별 정책 적용
```
