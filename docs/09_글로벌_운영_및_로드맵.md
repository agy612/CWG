## 2. 국가 추가 절차 (체크리스트)

새로운 국가/로또를 추가할 때 수행해야 할 작업 목록:

### 사전 조사
- [ ] 해당 국가 복권 법규 확인
- [ ] 대상 로또 게임 선정 (번호 구조, 추첨 주기)
- [ ] 추첨 결과 데이터 소스 확보 (공식 API/크롤링)
- [ ] 실물 티켓 샘플 수집 (OCR 학습용)

### 시스템 설정
- [ ] `game_configs` 테이블에 새 게임 등록
- [ ] `country_policies` 테이블에 국가 정책 등록
- [ ] 알고리즘 Config JSON 작성 (구간, 합계 범위 등)
- [ ] OCR 학습/테스트 (해당 국가 티켓 포맷)
- [ ] 추첨 결과 수집 크론 스케줄러 등록

### 구독 & 가격
- [ ] App Store / Google Play에 국가별 가격 설정
- [ ] 포인트 기본 지급량 설정

### 앱 현지화
- [ ] 앱 UI 번역 (해당 언어)
- [ ] 약관/개인정보 처리방침 현지화
- [ ] 알림 메시지 번역

### 테스트 & 출시
- [ ] 해당 국가 티켓 OCR 정확도 테스트 (목표 95%+)
- [ ] 중복 차단 Hash 로직 검증
- [ ] 추첨 결과 자동 수집 검증
- [ ] 구독 결제 플로우 검증
- [ ] 현지 베타 테스트
- [ ] 앱스토어 해당 국가 출시

## 3. 개발 로드맵

### Phase 1: MVP (0~3개월) — 4개 로또, 핵심 루프 검증

> 목표: "로또 선택 → 스캔 → 포인트 → 기본 통계" 루프가 작동하는 최소 제품 (4개 로또 동시 지원)

| 주차 | 마일스톤 | 상세 |
|------|---------|------|
| **1~2** | 프로젝트 셋업 | MSA 구성, DB 스키마, CI/CD, Docker 환경, Kafka 설정 |
| **3~4** | Ticket Service | 이미지 업로드, OCR 연동 (Google Vision), 텍스트 정제, 4개 로또 지원 |
| **5~6** | 검증 로직 | Hash 중복 차단, 낙첨 확인 (draw_results 연동), Rate Limiting |
| **7~8** | Reward Service | 포인트 원장, 기본 포인트 지급, 사용자 잔액 관리 |
| **9~10** | 앱 MVP | Flutter 앱 Android 빌드 (로또 선택, 카메라 스캔, 결과 확인, 홈, 포인트 이력) |
| **11~12** | 통합 & 베타 | 통합 테스트, 클로즈드 베타 (한국, 일본, 유럽 각 100명) |

**기술 스택:**
- 앱: Flutter (Dart) — Android MVP, iOS는 Phase 2
- 서버: Java 17+ / Spring Boot 3.x (MSA: Ticket, Reward, Algorithm)
- API Gateway: Spring Cloud Gateway
- DB: PostgreSQL 15+ / Redis 7+ / Kafka

**MVP 범위:**
```
포함:
  ✅ 로또 선택 화면 (4개 로또)
  ✅ 카메라 스캔 + 갤러리 업로드
  ✅ OCR → 번호 추출 (4개 로또 지원)
  ✅ Hash 중복 차단 + 낙첨 확인
  ✅ 기본 포인트 지급 (3-tier: FREE/STANDARD/PRO)
  ✅ 포인트 이력 조회
  ✅ 기본 통계 (최다/최소 출현 — 무료 공개)

미포함:
  ❌ 선택적 광고 보너스
  ❌ CWG 픽생성 (번호 추천)
  ❌ 챔피언십 (커스텀 필터 번호 생성)
  ❌ 프로모션/쿠폰 시스템
  ❌ 포인트샵
  ❌ iOS
```

### Phase 2: Growth (3~6개월) — 수익 모델 탑재

| 기능 | 상세 |
|------|------|
| **CWG 픽생성 (Level 1~2)** | 회차당 10개 고정, 핫/콜드넘버, 패턴 분석 기반 |
| **챔피언십** | 별도 탭, 20개 필터 기반 커스텀 번호 생성 (6개 전략 프리셋) |
| **구독 서비스 (2-Tier)** | STANDARD/PRO 플랜, 인앱 결제 (Google Play, App Store) |
| **선택적 광고 보너스** | FREE 1.5x, PRO 4.0x |
| **프로모션 시스템** | 4가지 타입 (POINT/COUPON/TICKET/DISCOUNT), 팝업 표시 |
| **쿠폰함** | 쿠폰 발급/사용, 수동 코드 입력 |
| **포인트샵** | 포인트로 구독권/챔피언십 티켓 구매 |
| **iOS 앱** | Flutter iOS 빌드 출시 |
| **메타데이터 검증** | EXIF, GPS 시공간 검증 |
| **바코드/QR** | QR 코드 스캔 지원 |

### Phase 3: Scale (6~12개월) — 기능 고도화

| 기능 | 상세 |
|------|------|
| **CWG 픽 Level 3** | 복합 모델, 낙첨 제외 역추론, 회차당 10개 유지 |
| **분석 리포트 고도화** | 상세 분석, 트렌드, 패턴 |
| **적중 내역 고도화** | CWG 픽/챔피언십 적중 추적 & 랭킹 |
| **챔피언십 고도화** | 사용자 간 필터 공유, 인기 전략 순위 |
| **관리자 대시보드** | 운영 통계, 정책 제어, 프로모션 관리 |
| **미국 시장 확장 준비** | Powerball + Mega Millions 추가 |

### Phase 4: Expand (12개월~) — 확장

| 기능 | 상세 |
|------|------|
| **일본/영국 시장** | 추가 국가 로또 지원 |
| **알고리즘 Level 4** | AI/ML 모델 적용 |
| **포인트몰** | 기프티콘/제휴 상품 교환 |
| **수동 입력** | OCR 실패 대비 수동 입력 |
| **스포츠 베팅** | 게임 타입 확장 |
| **B2B 데이터** | 분석 데이터 라이선스 |

## 5. 리스크 & 대응

| 리스크 | 영향 | 대응 |
|--------|------|------|
| OCR 인식률 저조 | 사용자 이탈 | QR 스캔 병행, 수동 입력 제공, OCR 모델 지속 개선 |
| 어뷰징 대량 발생 | 포인트 인플레이션 | 3단계 검증 강화, 일일 한도, 수동 입력 감산 |
| 구독 전환율 저조 | 수익 부족 | 추천 미리보기로 후킹, 포인트 소비 설계 조정 |
| 법적 리스크 (사행성) | 서비스 중단 | 법률 자문, 당첨 유도 아닌 데이터 분석임을 명확화 |
| 데이터 수집 속도 느림 | 알고리즘 가치 저하 | Phase 1에서 포인트 높게 지급하여 스캔 유도 |
| 스토어 수수료 (30%) | 마진 감소 | 연간 구독 유도, 장기적으로 웹 결제 검토 |
