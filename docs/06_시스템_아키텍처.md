## 2. 마이크로서비스 상세

### 2.1. Ticket Service

> 티켓 스캔, OCR, 검증, 낙첨 확인의 전체 플로우 담당

| 항목 | 내용 |
|------|------|
| **포트** | 8081 |
| **DB 테이블** | `tickets`, `draw_results` |
| **외부 연동** | OCR API (Google Vision / Naver Clova) |
| **이벤트 발행** | `ticket.verified` → Reward Service로 전달 |

**내부 플로우:**
```
이미지 수신 → S3 업로드 → OCR API 호출 → 텍스트 정제
→ Hash 생성 → 중복 확인 → 메타데이터 검증
→ 낙첨 여부 확인 (draw_results 대조)
→ status: VERIFIED → 이벤트 발행
```

### 2.2. Reward Service

> 포인트 적립/사용, 미션 관리, 구독 상태 관리

| 항목 | 내용 |
|------|------|
| **포트** | 8082 |
| **DB 테이블** | `users`, `transactions`, `missions`, `subscriptions` |
| **외부 연동** | 광고 SDK Callback, App Store/Google Play 결제 검증 |
| **이벤트 수신** | `ticket.verified` → 포인트 지급 처리 |

### 2.3. Algorithm Service

> 번호 추천 생성, 분석 리포트, 적중 평가

| 항목 | 내용 |
|------|------|
| **포트** | 8083 |
| **DB 테이블** | `recommendations`, `algorithm_configs`, `draw_results` |
| **배치 작업** | 추첨 결과 수집, 추천 세트 생성, 적중 평가 |
| **특이사항** | 읽기 위주 서비스, 배치 스케줄링이 핵심 |

## 4. 서비스 간 통신

| 구간 | 방식 | 설명 |
|------|------|------|
| Client ↔ Gateway | REST (HTTPS) | 동기 요청/응답 |
| Gateway ↔ Services | REST (HTTP) | 내부망 통신 |
| Ticket → Reward | Kafka Event | `ticket.verified` 이벤트로 비동기 처리 |
| Algorithm (배치) | 내부 스케줄러 | Spring Batch / @Scheduled |
| 정책 설정 | Redis 캐시 | 각 서비스가 Redis에서 정책 조회 |

│  │ • Reward   │  └───────────┘  │

> 사용자 증가 시 Kubernetes로 전환.

## 6. 보안

| 항목 | 방법 |
|------|------|
| 인증 | JWT (Access Token + Refresh Token) |
| HTTPS | TLS 1.3 필수 |
| 비밀번호 | 없음 (기기 기반 인증 + 소셜 로그인 확장) |
| API Key | OCR, 광고 SDK 키는 환경변수로 관리 |
| 이미지 | S3 pre-signed URL (직접 접근 차단) |
| 개인정보 | 최소 수집, 이미지 내 개인정보 마스킹 |
